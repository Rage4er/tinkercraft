## Решения (утверждены 2026-11-05)

1. **Хранение правки — операция с результатом.** Новая операция `edit_child_params`
   хранит `params` ребёнка и готовый меш результата (как `group` хранит
   `resultVertices/Indices/Normals`). Воспроизведение детерминировано и не требует CSG при
   загрузке. Минус — размер `.3dtc`; старые сборки не откроют файлы с новой операцией
   (`parse3dtc` отвергает неизвестные типы). Альтернатива «починить `rebuildBuildTree`»
   отклонена: это отдельная рискованная задача по ядру.
2. **Охват v1 включает вложенные CSG.** Требует поправки системы координат для
   переведённых внутренних CSG (см. «Риски»).

## Находки исследования (на чём строится дизайн)

- Операнды CSG удаляются из `objects` (`csgBoolean`); дети живут только в `treeStore`
  и в ранних операциях истории. Ребёнок не может быть в `selectedIds` →
  отдельное состояние `ui-store.selectedChild { rootId, nodeId }`.
- `treeStore` — не реактивный `Map`; UI читает read-модель `getTreeView(rootId)`
  (`csg/tree-view.ts`), пересчитываемую при смене `objects`.
- Единственный путь «пересчитать boolean из детей» — `rebuildNode` →
  `workerRebuildNode` → `handleRebuildTreeNode`; в проде сегодня его результат
  не используется (прогрев кэша). Он возвращает меш в COM-центрированном виде
  с запечённым TRS, а не в конвенции `SceneObject`.
- Конвенция CSG-результата: pivot = `transformA`, `v = S⁻¹Rᵀ(v_world − posA)`,
  **без** центрирования по COM → при смене params ребёнка pivot остаётся, меняются
  только вершины: `v = RS₀⁻¹(W_new − pos₀)`; затем пересчёт `aabb` и `originalBboxSize`.
- `rebuildBuildTree` (undo/load) никогда не чистит дерево и не воспроизводит
  `resize_dims`/`align`/`fillet`; снимок дерева (`serializeTree`) теряет
  `relativeToParent`/`mirroredPlane`. Поэтому правка только в дереве исчезнет.
- `.3dtc` не содержит узлов дерева — только `objects` и `operations`.

## Риски и открытые вопросы

- **Система координат ответа воркера.** `handleRebuildTreeNode` не возвращает COM-смещение;
  нужно расширить ответ (мировой меш/COM) или добавить сообщение. Расширение
  `rebuildTreeNode` не ломает ~12 мок-фабрик `worker-client` в тестах.
- **Вложенные CSG.** Внутренний CSG, перемещённый до того как стал операндом, имеет
  устаревшие `children` в системе создания; воркер это игнорирует («STALE»). Нужна
  поправка `TRS_cur·TRS₀⁻¹`.
- **Пустой результат.** Правка может обнулить subtract/intersect → 0 вершин,
  `computeAABB` даст ±Infinity: нужны защита, уведомление и откат.
- **Новая операция — в 4+ местах:** `VALID_OP_TYPES` (`io/3dtc-io.ts`, `io/doodle-io.ts`),
  `restoreOperationMeshArrays`, `Timeline.tsx` (`opIcon`/`opLabel`), `OP_FILTER_LABELS`,
  i18n `timeline.*`/`filters.*` (ru, en), `buildRebuildMeta`, `handleRebuildScene` (воркер),
  `rebuildBuildTree`.
- **Params неизменяемы:** снимки дерева хранят ссылки — правка только через `setNode` с новой копией.
- **Существующий баг рядом:** `resize_dims` на CSG записывает params без scale
  (теряется при пересборке без кэша).
- **Выбор ребёнка** сбрасывается при смене истории/выделения (`useSelectedChildGuard`).
- **Mirrored-дети** хранят одну плоскость (`mirroredPlane`), а на примитиве — список `mirrored[]`.

## Реализация 9.2 / 9.3 / 9.6 (итог)

**Ключевая находка — система координат.** Дети дерева хранят `localTransform` в системе СОЗДАНИЯ CSG
(мировые позиции на момент `csgBoolean`), а pivot корня после перемещений уже другой, при этом
вершины корня остаются в локальной системе исходного pivot (TRS₀ = TRS операнда A, он же
`resultCenter/Rotation/Scale` в операции `group`). Поэтому:

1. Воркер возвращает пересчёт поддерева в мире создания (`worldSpace: true` — корень НЕ центрируется по COM).
2. TRS₀ берётся из операции `group` корня (`findCreationTransform`).
3. `v = S⁻¹Rᵀ(v_world − pos₀)` (`unbakeToLocal`) — pivot корня (в т.ч. перемещённый) не трогаем.

**Калибровка вместо поправки `TRS_cur·TRS₀⁻¹`.** Вместо вывода TRS₀ для вложенных CSG из `relativeToParent`
(хрупко) перед правкой дерево пересчитывается со СТАРЫМИ params и сравнивается с текущим мешем
(bbox + объём). Совпало — тот же путь с новыми params заведомо корректен (проверено сравнением
с «свежим» CSG, в т.ч. вложенным и с RS). Не совпало — правка отклоняется (`tree_mismatch`):
типичный случай — вложенный CSG, сдвинутый до объединения (воркер считает внутренние boolean-ноды
в системе их создания; «STALE»). Это сознательное ограничение v1 вместо риска молча испортить геометрию.

**Undo/redo.** `rebuildBuildTree` теперь воспроизводит params/transform примитивов по префиксу истории
(`add_shape` сбрасывает, `resize_dims`/`edit_child_params` применяют). Меш корня при перемотке берётся
из `edit_child_params.result*` (`buildRebuildMeta`), кэш воркера обновляется `workerSyncMesh`.

**Остаётся (не в этой итерации):**
- 9.8 baked/mirrored дети — по-прежнему только просмотр.
- 9.9 индикатор `csgValid`/«правка недоступна» заранее (сейчас причина показывается уведомлением при попытке).
- Правка вложенного CSG, сдвинутого до объединения (нужна поправка `TRS_cur·TRS₀⁻¹` для inner boolean).
- Правка параметров не откатывается для undo «по полям» — одна операция на blur поля.
- Размер `.3dtc` растёт на меш каждой правки (решение 1); при частых правках разумно сжимать цепочку `edit_child_params` одного узла.

## Реализация 9.8

Выбрано представление «`primitive` + `TreeNode.mirrored: MirrorPlane[]`» вместо «baked + params»:
воспроизведение по истории синхронное (`rebuildBuildTree` воркер не вызывает), params остаются
единственным источником формы, а правка идёт общим путём `edit_child_params`. Воркер отражает примитив
в origin до TRS (`manifold.mirror`) — эквивалентно живой конвенции `world = TRS·mirror(v)`.
`registerObjectInTree` — единая точка регистрации операнда; `rebuildBuildTree` строит зеркального
операнда из params оригинала и `composeMirroredList` (раньше — НЕзеркальная копия, если объект уже
поглощён CSG).

**Не затронуто (осознанно):** baked-дети без params (импорт, вставленный CSG, запечённая копия при
зеркале всего CSG — `mirroredPlane`) остаются только для просмотра (причины `baked` / `mirror`).
Прочие ограничения прежние: вложенный CSG, сдвинутый до объединения (`nested_moved`), и 9.5.
*Обновление:* зеркало и вставка всего CSG теперь дают копию дерева — см. «CSG-INDEPENDENT-COPY» ниже.

## CSG-INDEPENDENT-COPY — независимая копия CSG (зеркало + вставка)

Зеркало и Ctrl+C / Ctrl+V CSG-результата дают **независимую параметрическую копию**: своё дерево
Build Tree, а не запечённый меш. Дети копии правятся общим путём 9.2/9.3 (`edit_child_params`).

**Решения (не менять без пересмотра):**

1. **Независимая, не связанная (не linked).** Правка копии не трогает оригинал, правка оригинала —
   копию. Копия — отдельные узлы дерева; общих узлов/ссылок с оригиналом нет. «Связанное зеркало» —
   отдельная задача, если понадобится, а не «починка» этой.
2. **Вставка — снимок на момент Ctrl+C.** `copySelected` кладёт в буфер снимок дерева
   (`ClipEntry.csgTree`: `snapshotSubtree` — глубокая копия узлов без кэшей) и систему создания;
   `pasteClipboard` пишет тот же снимок в операцию (`GroupOperation.copyTree`, `ids: []`). Правка
   оригинала ПОСЛЕ копирования во вставку не попадает — так и задумано (снимок, не ссылка). По этой
   же причине история хранит снимок, а не id источника: при воспроизведении источник мог измениться.
3. **Зеркало — копия источника в этот момент истории.** Снимок не нужен: зеркало создаётся сразу,
   и `rebuildBuildTree` в шаге `mirror` копирует дерево источника по префиксу истории
   (`copySubtree(id, newId, plane)`), перезаписывая узлы копии. Мировые трансформы узлов отражаются
   (`mirrorTreeNode`), примитивы получают плоскость в `mirrored[]` (9.8; не запекаются), baked-узлы
   отражают вершины. Меш объекта сцены — по-прежнему прямое отражение вершин `M·v`.
4. **Детерминированные id узлов копии:** корень — id копии, остальные — `${idКопии}:${idУзлаИсточника}`
   (`copyNodeId`). Иначе `edit_child_params.nodeId` правки ребёнка копии не находил бы узел после
   перемотки/загрузки (дерево копии строится заново). Копия копии — `${c2}:${c1}:${id}`.

**Система создания копии — `findCreationTransform` (`store/edit-child.ts`).** Правка ребёнка
переводит мировой меш дерева в локальную систему корня через TRS₀ (система, в которой заданы мировые
трансформы детей). У копии нет своей операции `group` с операндами, поэтому без этого правка
упиралась бы в `no_origin` даже без замков. Правила (при касании функции — сохранить):

- **зеркальная копия** (`mirror`, `ids[k] === rootId`) → TRS₀ источника `originalIds[k]` по префиксу
  истории ДО шага зеркала, отражённый той же плоскостью: `mirrorPoint(pos)`, `mirrorEuler(rot)`,
  `|scale|`; рекурсивно (зеркало зеркала, зеркало вставки), глубина ≤ `MAX_COPY_CHAIN` = 64.
  Обоснование: дерево копии = отражённое дерево источника, вершины = `M·v` источника, а
  `S⁻¹·R'ᵀ·M = M·S⁻¹·Rᵀ` при `R' = M·R·M`;
- **вставка с деревом** (`group`, `ids: []`, `copyTree`) → `copyTree.origin` — TRS₀ источника на
  момент Ctrl+C (узлы снимка заданы в его системе, вершины вставки = вершины источника);
- **старая вставка без дерева** (`ids: []`, без `copyTree`) → `null` (`no_origin`), как раньше;
- обычный CSG → `resultCenter/Rotation/Scale` операции `group`, как раньше.
- Функция работает по эффективной истории (`projectHistory`): правка плоскости шага зеркала (9.5.3)
  меняет систему копии, и каскад пересчитывает правки её детей (тест в `independent-copy-mirror`).

**Замки.** `mirror` — только у примитива, запечённого старым зеркалом CSG (baked с params; новые не
создаются). Настоящий baked-меш (импорт, старая вставка без дерева), в том числе отражённый — `baked`.

**Совместимость.** Старые проекты: при загрузке зеркальный CSG получает дерево по истории (раньше —
заглушка-куб, MIRROR-CSG-TREE-RELOAD); старые вставки без `copyTree` остаются запечёнными.
Попутно: операция вставки пишет полный TRS (`resultRotation`/`resultScale`, PASTE-CSG-RS).

(в т.ч. именованные регресс-тесты MIRROR-CSG-TREE-RELOAD и PASTE-CSG-RS — проверены откатом
фиксов), `io/3dtc-io.test.ts`; e2e `pnpm e2e:independent-copy` (проверен откатом: старое зеркало —
«замок 🔒 mirror», старая вставка — «не раскрывается — запечённый меш»).
