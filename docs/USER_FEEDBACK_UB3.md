## Детали по пунктам

### UB3-1. Дневной счётчик реварда импорта считает показы, а не импорты 🟡 P1

**Что ожидает пользователь:** `(0/3)` = «оплаченных рекламой импортов сегодня: 0 из 3». Серия из 2 роликов оплачивает **один** импорт, значит за сутки должно быть доступно **3 импорта** (до 6 показов).

**Что в коде (текущее поведение — «показы», и оно же в спеке):**

| Факт | Место |
|---|---|
| `importAdCount = adRewards.import.countToday` — счётчик показов вида `import` | [`ImportModal.tsx:28`](../web-app/src/components/ImportModal.tsx) |
| `adCost = 2` — цена импорта в роликах | [`ImportModal.tsx:39`](../web-app/src/components/ImportModal.tsx) |
| Подпись `(done/max)` = `(countToday/3)` | [`ImportModal.tsx:153-159`](../web-app/src/components/ImportModal.tsx), ключ `import.watchAd_few` = «Посмотреть {{adsNeeded}} рекламы {{series}}/{{adsNeeded}} ({{done}}/{{max}})» ([`ru/translation.json:158-161`](../web-app/src/i18n/locales/ru/translation.json)) |
| `markAdWatched()` поднимает `countToday` **на каждый показанный ролик** | [`economy-store.ts:82-92`](../web-app/src/store/economy-store.ts) |
| `watchAdsForImport()` проверяет `LIMITS.adsPerDay` до серии и в середине серии, `countToday` растёт в цикле | [`economy-store.ts:866-915`](../web-app/src/store/economy-store.ts) (:872, :894, :903-905) |
| `adsPerDay: 3` — единый лимит показов на вид | [`economy-config.ts:84`](../web-app/src/store/economy-config.ts) |
| Кнопка дизейблится, если показов не хватает на полную серию: `importAdCount + adCost > 3` | [`ImportModal.tsx:148`](../web-app/src/components/ImportModal.tsx) (подсказка `economy.adLimit` — :161-165) |

**Последствия (важно, это не только текст):**

1. После **одного** импорта `countToday = 2` → подпись `(2/3)` (ровно как написал пользователь), и `2 + 2 > 3` → кнопка неактивна до следующего дня. То есть рекламой реально оплачивается **1 импорт в сутки, а не 3**.
2. Даже если бы лимит пропускал (например, `countToday = 2 < 3` при другом пороге), серия оборвалась бы на середине: цикл в `watchAdsForImport` прерывается по `isLimitReached` (:894), `watchedCount (1) < count (2)` → `return false` (:914) → **импорт не оплачен, но ролик уже показан** (показ потерян).
3. Спека сейчас описывает поведение кода: [`ECONOMY.md`](../ECONOMY.md) v2.4 §2 — «Реклама за импорт (вид `import`, серия из 2) … ≤3 показа/день на вид». Значит UB3-1 — **изменение спеки**, а не только исправление кода.

**Предлагаемое решение (вариант A, рекомендуемый):** разделить «показы» и «оплаченные операции».

- В `AdRewardState` ([`economy-store.ts:53-58`](../web-app/src/store/economy-store.ts)) — поле `opsToday` (число завершённых оплаченных операций вида); инкремент **только по полной серии** (там же, где `watchedCount >= count`).
- `LIMITS`: `adsPerDay` → per-kind (`import`: `importsPerDay = 3` и `adsPerDay = 6` показов; `tokens`/`export`/`banner` остаются «1 показ = 1 операция», там счётчик и так корректен).
- UI `ImportModal`: `done = opsToday`, `max = 3`, `disabled = opsToday >= 3 || showsLeft < adCost`.
- Миграция: persist `version: 4 → 5` ([`economy-store.ts:1581-1587`](../web-app/src/store/economy-store.ts)) + санитайзеры (`sanitizeAdRewards` — clamp `countToday` к `LIMITS.adsPerDay`, :509-536; `sanitizeEconomyData`, :544) + облачный контракт (`collectSyncData`/`loadFromCloud`/`partialize`, :1609).
- Спека: `ECONOMY.md` → v2.5 (§2 таблица рекламы: «3 импорта/день, 2 ролика на импорт = до 6 показов», §5 счётчики).
- Тесты: 1 импорт → `(1/3)` + кнопка ещё активна; 3 импорта → `(3/3)` + disabled; частичная серия не увеличивает `opsToday`, но списывает показы.

**Вариант B (минимальный, не решает блокировку):** оставить счётчик показов, добавить рядом вторую подпись «импортов сегодня: X/3». Не рекомендуется — не чинит «второй импорт невозможен».

**Критерии готовности:** после 1 импорта подпись «Посмотреть 2 рекламы 0/2 (1/3)», кнопка активна; ещё 2 импорта проходят; на 4-м — disabled + подсказка лимита; дневной максимум показов вида `import` = 6.

### UB3-3. Дебаг-режим: как накрутить токенов (нужен стартовый счёт 3000) 🟡 P1

**Ответ на вопрос «как сейчас» — штатного способа нет.**

- Приложение **не читает URL-параметры**: `grep URLSearchParams|location.search|searchParams` по `web-app/src` → 0 совпадений. `?debug-mode=16` и `?draft=true` — параметры **консоли/платформы Яндекс Игр** (режим отладки и черновика сборки), нашим кодом они не обрабатываются; `?lang=ru` тоже не читается — язык определяется SDK/`navigator`/`<html lang>` ([`i18n/init.ts:35-77`](../web-app/src/i18n/init.ts)).
- Стартовый баланс — `tokens: 0` ([`economy-store.ts:658`](../web-app/src/store/economy-store.ts)); API `addTokens(amount)` существует (:687-689), но store **не выставлен в `window`** (`grep window.__` → 0 совпадений), поэтому «в консоли нажать addTokens» тоже недоступен.
- Ручная правка `localStorage` ключа `tinkercraft-economy` (:1581, `version: 4` :1587) **ненадёжна**: при старте выполняется `loadFromCloud()` ([`App.tsx:233`](../web-app/src/App.tsx)) со стратегией keep-local/cloud-wins (EC-R5), а `syncToCloud()` идёт каждые 30 с ([`App.tsx:252-254`](../web-app/src/App.tsx)) — облако может перезаписать локальную накрутку.

**Сколько нужно для теста Pro:** аренды 75 + 75 + 50 ([`PropertiesPanel.tsx:272-274`](../web-app/src/components/PropertiesPanel.tsx)), подписки 700/неделя и 2000/месяц ([`economy-config.ts:32-33`](../web-app/src/store/economy-config.ts)) → **3000 TC** покрывает месячную подписку и все аренды одновременно. Цифра пользователя обоснована.

**Предлагаемое решение (к обсуждению):** debug-хук по **нашему** параметру URL, например `?debug-tokens=3000` (или `?debug-economy=1` → grant по умолчанию 3000):

1. Разовый grant **ПОСЛЕ** `loadFromCloud()` в bootstrap экономики ([`App.tsx:229-249`](../web-app/src/App.tsx)) — иначе облако перезатрёт.
2. Условие включения: `import.meta.env.DEV` **ИЛИ** явный параметр в draft-сборке; в релизной сборке без параметра — полный no-op.
3. Защита от накрутки/модерации: флаг «уже выдано в этой сессии», значение не отправлять в `collectSyncData` как заработок, и обязательно — **отключено по умолчанию** (выдача премиум-валюты в проде = риск модерации Яндекс Игр).
4. Побочный бонус: тот же хук полезен для ручных проверок UB3-1 (лимиты импорта) и кулдаунов.

**Открытые вопросы:** имя параметра; выдавать ли 3000 автоматически при `debug-mode` платформы; что делать с уже непустым балансом (доплачивать до 3000 / ставить 3000 / не трогать); сбрасывать ли дневные лимиты вместе с токенами.

**Критерии готовности:** на draft-сборке по параметру баланс становится ≥3000 TC, хватает на месячную подписку и все три аренды; без параметра поведение не меняется.

### UB3-4. Бейджи на кнопках «Экспорт»/«Импорт» перекрывают кнопки — убрать заливку 🟢 P2

**Факт.** На тулбаре по два бейджа на кнопку ([`Toolbar.tsx:168-176`](../web-app/src/components/Toolbar.tsx)): экспорт — `type="tokens" value="50"` + `type="ad" value="1"`, импорт — `value="100"` + `value="2"`. `Badge` абсолютно позиционирован по углам родителя с оффсетами −3px и имеет **сплошную заливку + тень** ([`Badge.tsx:24-39`](../web-app/src/components/Badge.tsx): `boxShadow` :34; фоны: `#f59e0b` :47, `#fbbf24` :52, `#10b981` :60/:71/:77, `#8b5cf6` :64). Иконки 14px внутри контейнера 14×12 — на кнопке 32px-иконки цветные пятна закрывают углы.

**Предлагаемое решение:** убрать заливку (`background: 'transparent'`, `boxShadow: 'none'`), оставить иконку + число; читаемость на любом фоне обеспечить текстовой обводкой/тенью (`text-shadow`, `-webkit-text-stroke`) и сохранением цветового акцента в самой иконке. Либо полупрозрачная подложка (`background: rgba(…0.25)`) — но пользователь просит именно «убрать заливку».

**Область влияния:** `Badge` используется не только в тулбаре (например, бейдж цены 3D-текста в [`LeftPanel.tsx`](../web-app/src/components/LeftPanel.tsx)) → решить: прозрачный стиль глобально или только для тулбара (проп `flat`/`variant`). Обновить [`Badge.test.tsx`](../web-app/src/components/Badge.test.tsx) и [`ECONOMY.md`](../ECONOMY.md) §6.4 (стиль бейджей).

**Критерии готовности:** на кнопках «Экспорт»/«Импорт» под бейджами читается иконка кнопки; цифры цены/реварда остаются читаемыми.

### UB3-5. «Уже получено» после ежедневного бонуса → иконка подарка + обратный таймер 🟢 P2

**Факт.** Пока бонус доступен — кнопка с иконкой подарка и «+50» ([`PropertiesPanel.tsx:168-177`](../web-app/src/components/PropertiesPanel.tsx)); после получения вместо кнопки рендерится `<ClockIcon width={14}/> уже получено` (:179-181, ключ `economy.bonusClaimed` = «уже получено», [`ru/translation.json:474`](../web-app/src/i18n/locales/ru/translation.json)) — без слова «бонус» и без указания, когда вернётся. Рядом в той же строке так же выглядит статус рекламы («ждём м:сс»/«Лимит рекламы», :194-200) — отсюда неразличимость. В [`EconomyMiniHUD.tsx:78-82`](../web-app/src/components/EconomyMiniHUD.tsx) бонус после получения показывается как подарок + «—» (и пересчитывается только при смене `lastDailyBonus`, :31-39 — после полуночи без перемонтирования останется «—»).

**Как считать таймер.** День определяется календарной датой серверного времени: `isDayPassed()` сравнивает `getFullYear/getMonth/getDate` от `new Date(serverTime)` ([`economy-config.ts:127-139`](../web-app/src/store/economy-config.ts)), а `getServerTime()` возвращает epoch-мс с кэшем 30 с и фолбэком на `Date.now()` ([`server-time.ts:22-53`](../web-app/src/platform/server-time.ts)). ⚠️ Разбор даты идёт в **локальной таймзоне браузера**, поэтому «сброс в полночь по серверному времени» фактически = полночь локальной TZ клиента, скорректированная по серверному смещению. Это надо учесть в таймере (и, при желании, отдельно уточнить в спеке).

**Предлагаемое решение:**

- Сохранить `GiftIcon`, вместо «уже получено» показывать тикающий остаток до сброса бонуса: `🎁 07:12:45` (формат `ч:мм:сс`).
- Новый хук `useDailyReset(lastDailyBonus)` рядом с `useAdCooldown()` в [`platform/ad-timers.ts`](../web-app/src/platform/ad-timers.ts) — посекундный пересчёт по локальным часам с поправкой `getServerTimeOffset()` (:70-75), тот же паттерн, что уже починил U2.
- Единый вид в `PropertiesPanel` и `EconomyMiniHUD` (в HUD — заменить «—» на тот же отсчёт).
- i18n: новый ключ `economy.bonusResetsIn` («бонус через {{time}}» / "bonus in {{time}}"). Готовые `export.bonusCooldown` = «До {{time}}» и `export.bonusClaimed` = «Уже получено» ([`ru/translation.json:149-151`](../web-app/src/i18n/locales/ru/translation.json)) лежат в неймспейсе `export` и **мёртвые** — из этого блока в коде используется только `export.adCooldown` ([`ExportModal.tsx:206`](../web-app/src/components/ExportModal.tsx)); их можно либо перенести в `economy.*`, либо удалить за ненадобностью.
- Тултип `economy.tooltip.bonusDesc` (:426) дополнить фразой про полночь, чтобы подпись была самодостаточной.

**Критерии готовности:** после получения бонуса в панели виден подарок + убывающий `ч:мм:сс`; при переходе порога кнопка снова становится активной без перезагрузки страницы.
