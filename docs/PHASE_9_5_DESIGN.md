# PHASE_9_5_DESIGN.md — правка шагов fillet / extrude / mirror / move

> Ветка `phase-9`, база `0c70fbf` (511 тестов). Статус: **решения §10 утверждены (2026-11-05)**;
> **9.5.0 реализован** (§11); **9.5.1 (fillet) отменён** — fillet удалён из приложения (§12); **9.5.2 (move) реализован** (§13); **9.5.3 (mirror) реализован** (§14); 9.5.4 — впереди. Контекст 9.1–9.9 — `docs/PHASE_9_DESIGN.md`.

## 1. Проблема

- **9.2/9.3 (сделано)** — правка params ребёнка CSG = **новая операция** `edit_child_params` над
  ТЕКУЩИМ состоянием. Прошлые шаги не меняются; Timeline ✎ (9.4) ведёт к цели шага, а не к самому шагу.
- **9.5** — изменить параметры **существующего шага N** (радиус fillet, delta move, плоскость mirror,
  глубина extrude) так, будто он сразу был выполнен с новыми значениями. Всё, что после N, должно
  стать таким, каким было бы при новых значениях.
- **Каскад.** История хранит часть результатов «замороженными» (готовые меши). Они не пересчитываются
  при воспроизведении, поэтому после правки шага N их надо пересчитать заново.

### 1.1 Что в истории заморожено, а что воспроизводится (инвентаризация кода)

| Операция | Что хранит | При воспроизведении (`rebuildFromHistory` / `rebuildBuildTree`) | Зависит от шага N? |
|---|---|---|---|
| `add_shape` | params, transform | воркер строит из params | нет (корень) |
| `import_mesh` | исходные вершины | как есть | нет (корень) |
| `move` | delta / rotDelta / scaleDelta (относительные) | `applyMoveDelta` | композиция — пересчитывается сама |
| `fillet` | id, radius | воркер `buildPrimitiveWithFillet` | пересчитывается сама |
| `mirror` | originalIds, ids, plane | `applyMirrorToTransform` + зеркало вершин; для примитива — `composeMirroredList` | пересчитывается сама |
| `resize_dims` | params | воркер / scale | пересчитывается сама |
| `align` | axis, anchor, anchorId, **deltas (готовые числа)** | применяет записанные deltas | ⚠ записан **результат**, а не намерение |
| `group` | **resultVertices/Indices/Normals, resultCenter/Rotation/Scale, originalBboxSize** | берёт сохранённый меш (CRIT-CSG-2) | ❄ **заморожено** |
| `edit_child_params` | **resultVertices…, originalBboxSize** | берёт сохранённый меш | ❄ **заморожено** |

Выводы:
1. Каскад нужен только для **замороженных** операций (`group`, `edit_child_params`) и для `align`
   (там записан результат, а не намерение). Остальное воспроизводится само.
2. **Extrude не имеет своей операции.** `extrudeSelected` пишет пару `add_shape` (плита-куб; её params
   **и transform** зависят от depth/axis) + `group` (union без `resultRotation/Scale`/`treeOperation`).
   Восстановить «глубину» из истории нельзя: старые extrude не отличить от ручного «куб + объединение».
3. **`group.resultCenter/Rotation/Scale` = TRS операнда A на момент объединения.** Правка `move`
   операнда до объединения меняет не только меш, но и pivot результата.
4. **Запасной путь воркера** (group без `resultVertices`) считает CSG, но `rebuild.ts` центрирует его
   по COM (legacy-конвенция CENTERING-RESIDUAL), а живой `csgBoolean` даёт pivot = `transformA` и
   un-bake RS. **Каскад не может опираться на `rebuildFromHistory`** «как есть»: получится другая
   конвенция pivot/вершин.

## 2. Подходы

### Подход A — переписывание истории (rewrite in place)

- Мутировать `operations[N]`, пересчитать и **перезаписать** замороженные payload'ы шагов N+1…end.
- **Плюсы:** история и `.3dtc` чистые, без «наслоений».
- **Минусы и риски:**
  - Undo сейчас — это **индекс** в массиве операций (`historyIndex`). Отменить переписывание нечем:
    нужен отдельный стек «записей переписывания» (старые операции N…end) — второй механизм undo
    рядом с первым.
  - **Снимки** (`snapshots.ts`, ключ — индекс) для индексов ≥ N становятся неверными → сброс
    кэша, медленный undo/redo после правки.
  - Хвост redo (`historyIndex < length`) после переписывания нужно либо пересчитывать, либо отбрасывать.
  - Ошибка посреди каскада оставляет историю в полупереписанном состоянии, если не делать копию.

### Подход B — дополняемая история (append, как 9.2/9.3)

- Новая операция `edit_step` в конец: «шаг N теперь с такими params» + готовые результаты каскада.
- `operations[N]` **не трогается**.
- **Плюсы:** undo/redo — тот же индекс, что сейчас; снимки всех прежних индексов остаются верными
  (префикс не меняется); правка атомарна (операция либо добавлена целиком, либо нет).
- **Минусы:** история растёт; каждая правка хранит меши всех пересчитанных CSG → `.3dtc` растёт.
- **Риск:** все потребители истории должны видеть **эффективные** params шага N, а не исходные.

### Рекомендация: B, уточнённый «проекцией истории» (B′)

Принимаю направление ТЗ (append), но с уточнением — без него B не работает:
`buildRebuildMeta` идёт по операциям **по порядку**, и правка, лежащая в конце, не может
«задним числом» изменить шаг N.

**Проекция.** Чистая функция
`projectHistory(ops: TinkerCraftOperation[]): TinkerCraftOperation[]` строит **эффективную**
историю:
1. собирает все `edit_step` из префикса (последняя правка шага побеждает);
2. возвращает копию операций, где у шага N подставлены новые params, а у затронутых замороженных
   шагов — новые payload'ы из `edit_step.replacements`; сами `edit_step` из результата выбрасываются.

Все существующие потребители (`buildRebuildMeta`, `rebuildFromHistory`, `rebuildBuildTree`,
`findCreationTransform`, воркер `rebuildScene`) получают **эффективную** историю и не меняются
внутри. Сырые операции остаются в сторе и в `.3dtc` (там проекция строится при загрузке).
Изменение — в одной функции и в местах, где история передаётся потребителям (§7, риск R5).

## 3. Каскадный rebuild

### 3.1 Множество затронутых (dependency closure)

Правка шага N затрагивает множество объектов `S`:

| Шаг N | Начальное `S` |
|---|---|
| `fillet {id}` | `{id}` |
| `move {ids}` | `ids` |
| `mirror {originalIds, ids, plane}` | `ids` (новые объекты) |
| extrude (пара `add_shape` плиты + `group`) | `{slabId}` |

Проход по шагам N+1…end:
- `group` с операндом из `S` → **пересчитать** (меш + resultCenter/Rotation/Scale + originalBboxSize);
  resultId добавить в `S`;
- `mirror` с `originalIds ∩ S` → `ids` добавить в `S` (пересчитается сам, это не замороженная операция);
- `edit_child_params` с `rootId ∈ S` → **пересчитать** (путь 9.3 по дереву, с калибровкой);
- `align` с `ids ∩ S ≠ ∅` → политика §3.3;
- `delete` → убрать id из `S`.

`K` — число пересчитываемых замороженных шагов, обычно небольшое: только CSG «ниже по течению»
от изменённого объекта, а не все CSG после N.

### 3.2 Движок пересчёта

Нужен **пошаговый воспроизводитель** в той же конвенции, что и живые действия:

1. Старт — состояние **до шага N**: снимок индекса N (`getCachedSnapshot(N)`, префикс не менялся)
   или `rebuildFromHistory(effective[0..N))`.
2. Применить изменённый шаг N.
3. Для шагов N+1…end: незамороженные — тем же кодом, что воспроизведение (`rebuildOps.ts`,
   worker build/fillet/mirror); замороженные из `S` — **живым ядром CSG**.
4. **Обязательный рефакторинг:** вынести из `csgBoolean` чистую функцию
   `computeCsgResult(objA, objB, op) → { vertices, indices, normals, transform, originalBboxSize }`
   (sync операндов в воркер → boolean → сдвиг COM→transformA → un-bake RS). Её используют и
   `csgBoolean`, и каскад — одна конвенция; без неё каскад даст pivot = COM (находка 1.1 п. 4).
5. Пересчёт `edit_child_params` — существующий `computeEditedChild` на дереве, построенном из
   эффективной истории.
6. Результат: список `replacements` (по индексам шагов) → в `edit_step`. Если любой шаг дал пустую
   или не-manifold геометрию — **отказ всей правки** (ничего не добавляется, уведомление «шаг M стал
   пустым»).

**Производительность.** O(M) дешёвых шагов (трансформы) + O(K) вызовов CSG воркера. Простые примитивы
дают ~10–30 мс на CSG (видно по e2e: «CSG: 17 мс»), поэтому 10 CSG < 1 с. Дорогие случаи — fillet,
тор, импортированные меши. Оптимизации:
- старт со **снимка индекса N** (не пересобирать префикс);
- пропускать шаги вне `S`;
- для UI-превью — debounce, коммит только по blur/Enter (как `NumInput`).

### 3.3 Политика `align` (решение пользователя, §10 В2)

`align` хранит готовые deltas. После правки `move` до выравнивания:
- **Буквально (literal):** применить записанные deltas — объекты сдвинутся, «выравнивание» сломается
  (история честно воспроизводит то, что было записано);
- **По намерению (re-solve):** пересчитать deltas из `axis/anchor/anchorId` по bbox объектов на этом
  шаге. Данных в операции достаточно; deltas попадают в `replacements`.

Рекомендация: **re-solve** (ожидание пользователя CAD — «выровнено» остаётся выровненным). Но это
расширяет `replacements` на незамороженные шаги, поэтому в 9.5.1 (fillet) не нужно: fillet bbox
куба не меняет.

### 3.4 Кэш снимков

- Снимки индексов `< len(ops)` остаются верными: префикс не меняется (главный выигрыш B′).
- Новый индекс (после `edit_step`) кэшируется как обычно (`cacheSnapshotWithTree`).
- Дерево: `rebuildBuildTree(effective…)` строит его из эффективной истории (тот же путь, что после 9.6/9.8).

## 4. Undo / redo

- `edit_step` — обычная операция: **undo** = `historyIndex − 1` → проекция без этой правки →
  исходные значения и исходные замороженные меши; снимок прежнего индекса уже в кэше (мгновенно).
- **redo** = `historyIndex + 1` → снимок/проекция с правкой.
- `originalParams` для undo **не нужны** (отмена — по индексу); хранятся только для подписи в Timeline
  («fillet r 2 → 3») и для проверки отпечатка.
- Новая правка при `historyIndex < length` отбрасывает хвост redo — как любое действие сейчас.
- Несколько правок одного шага: в проекции побеждает последняя; undo снимает их по одной.

## 5. Типы

```ts
/** Фаза 9.5: правка параметров прошлого шага (append-only; см. projectHistory). */
export interface EditStepOperation {
  type: 'edit_step'
  /** Индекс шага N в operations (префикс неизменен, индекс стабилен) */
  stepIndex: number
  /** Отпечаток шага N: защита от рассинхрона (тип + id цели); не совпал → правка игнорируется с предупреждением */
  stepFingerprint: { type: TinkerCraftOperation['type']; targetId: string }
  /** Новые значения — по типу шага */
  patch:
    | { kind: 'fillet'; radius: number }
    | { kind: 'move'; delta: Vec3; rotDelta?: Vec3; scaleDelta?: Vec3 }
    | { kind: 'mirror'; plane: MirrorPlane }
    | { kind: 'extrude'; depth: number }            // 9.5.4, только для group.source = 'extrude'
  /** Прежние значения — только для подписи в Timeline / диффа */
  before?: EditStepOperation['patch']
  /** ОБЯЗАТЕЛЬНО: пересчитанные замороженные шаги (детерминизм без CSG при загрузке — решение 1 Фазы 9) */
  replacements: Array<{
    stepIndex: number
    kind: 'group' | 'edit_child_params' | 'align'
    resultVertices?: Float32Array | number[]
    resultIndices?: Uint32Array | number[]
    resultNormals?: Float32Array | number[]
    resultCenter?: Vec3
    resultRotation?: Vec3
    resultScale?: Vec3
    originalBboxSize?: Vec3
    deltas?: Record<string, number>                  // для align (re-solve)
  }>
}
```

Отличие от ТЗ: в ТЗ `resultMeshes` был «опционально, для скорости». Здесь он **обязателен**: без него
при загрузке потребовался бы CSG (нарушение решения 1), а запасной путь воркера даёт другую конвенцию
pivot (§1.1 п. 4).

Для 9.5.4 к `GroupOperation` добавляется необязательное поле
`source?: { kind: 'extrude'; baseId: string; slabId: string; axis: 'X'|'Y'|'Z'; depth: number }`,
которое пишет `extrudeSelected`. Старые extrude-пары без него не редактируются как extrude.

Регистрация новой операции — тот же список мест, что у `edit_child_params`: `VALID_OP_TYPES` (3dtc,
doodle), `restoreOperationMeshArrays` (массивы в `replacements`), Timeline `opIcon/opLabel`,
`OP_FILTER_LABELS`, i18n.

## 6. UI

- **Timeline:** ✎ (как в 9.4) у шагов `fillet`, `move`, `mirror` и, в 9.5.4, у extrude-`group`.
  Только для шагов ≤ `historyIndex`.
- **Форма:** рекомендую **панель справа «Шаг N»** (как `ChildPropertiesPanel`), а не модалку:
  - на ветке `yandex-games` каждая модалка должна ставить геймплей на паузу (`isAnyModalOpen`) —
    новая модалка расширяет дифф merge;
  - единый стиль с 9.2 (`NumInput`, коммит по blur/Enter).

  | Шаг | Поля |
  |---|---|
  | fillet | radius (`FILLET_MIN_RADIUS` … максимум по кубу − `FILLET_EPSILON`) |
  | move | ΔX/ΔY/ΔZ, Δrot, Δscale (по `kind`) |
  | mirror | плоскость YZ / XZ / XY |
  | extrude | глубина (ось — только просмотр) |

- **Эффективные значения в Timeline:** шаг N показывает новые значения и метку «изменён (шаг M)»;
  сама `edit_step` подписана «Правка шага N: fillet r 2 → 3».
- **Индикация (9.7):** «Пересчёт: k из K…» на время каскада; при отказе — уведомление с номером

## 8. Тест-план

**Unit (без WASM):**
1. `projectHistory`: без `edit_step` — тождество (тот же массив по значениям).
2. Подстановка patch в шаг N; последняя правка побеждает; `edit_step` выброшены из результата.
3. Несовпадение `stepFingerprint` → правка игнорируется.
4. Dependency closure: fillet → `S` распространяется через `group`/`mirror`, обрывается на `delete`.

**Интеграция (worker-bridge, реальный WASM):**
5. **fillet:** куб r=2 → union со сферой → правка fillet r=3 → результат = «свежий» сценарий с r=3
   (мировой bbox + объём, допуск 1e-3 отн.; diff вершин < 1e-4 там, где топология совпадает).
6. **Конвенция:** `computeCsgResult` = прежний `csgBoolean` (pivot = transformA, un-bake RS) —
   существующие `csg-preserve-rs` и `render-data-invariant` зелёные.
7. **move:** правка delta операнда A до union → resultCenter и меш = свежий сценарий.
8. **mirror:** правка плоскости YZ → XZ → зеркальная копия и CSG ниже = свежий сценарий.
9. **Каскад K>1:** fillet → union → union → правка fillet → оба CSG пересчитаны.
10. **edit_child_params ниже по течению** пересчитан и проходит калибровку 9.9.
11. **Undo** → исходные меши побайтно (снимок); **undo со сброшенными снимками** → то же через
    `rebuildFromHistory(effective)`; **redo** → правленые.
12. **Отказ:** правка, обнуляющая subtract ниже по течению → история и объекты не изменились, есть уведомление.
13. **`.3dtc` round-trip:** `serialize3dtc`/`parse3dtc` → проекция → те же объекты.
14. **Производительность:** 10 CSG после N (простые примитивы) — каскад < 1 с (порог в тесте с запасом
    для CI, например 3 с; фактическое время — в лог).

**E2E (Playwright, `e2e:edit-step`):**
15. Куб → fillet → union со сферой → ✎ у шага fillet → радиус → CSG обновился, undo вернул.

## 9. Альтернативы и объём

- **C — rewrite с журналом.** Подход A плюс отдельный стек «переписываний» для undo. Чистая история,
  но два механизма undo и сброс снимков ≥ N. Отклонено для v1; годится как «Сжать историю» (R6) —
  явная команда пользователя, после которой undo через точку сжатия невозможен.
- **Только fillet в первой итерации** — рекомендую как поэтапный объём (ниже).
- **«Только один CSG после N»** (из ТЗ) — **не рекомендую**: движок либо умеет K шагов, либо нет.
  Предел K=1 почти не упрощает код, но создаёт непредсказуемое для пользователя ограничение. Разумнее
  общий предел K (R4).
- **Только «по намерению» без хранения результатов** (пересчитывать CSG при каждой загрузке) — дешевле

Уточнения относительно §2–§5:
- **Где проецировать (R5).** Проекция стоит не на местах вызова, а на входе функций-потребителей.
  Она идемпотентна (без `edit_step` возвращает тот же массив, O(n) проверка), поэтому сырая
  история физически не доходит до воспроизведения, даже если новое место вызова забудет её
  спроецировать. Стор (`jumpToHistoryInner`, загрузка, автосейв) не менялся.
- **Сигнатура.** `projectHistory(ops, { stepIndex, patch }?)`: второй аргумент — гипотетическая
  (ещё не записанная) правка, вход для каскада 9.5.1 («история, как если бы шаг N сразу был с
  новыми значениями»; замороженные шаги ниже — старые, их пересчитывает каскад).
- **`StepReplacement.params`** (для `edit_child_params`): правка fillet/resize ребёнка, позже
  отредактированного через 9.3, должна обновить и params в дереве, а не только меш.
- **Атомарность в проекции:** любая неверная замена (не тот тип шага, индекс вне `(N, i)`)
  отбрасывает всю правку — частичный каскад несогласован.
- **Extrude** (`patch.kind = 'extrude'`, `GroupOperation.source`) — в 9.5.4, вместе с записью `source`.
- **Порядок в `computeCascade` для `align`:** цель из S → шаг пересчитывается; якорь из S → все цели
  сдвигаются и входят в S.

**Находка (блокер 9.5.1) — FILLET-LOST-IN-CSG.** CSG с кубом после fillet теряет скругление:
`handleCsgBooleanSync`/`handleSyncObjects`/`rebuildTreeNode` воркера строят примитив через
`buildPrimitive` без `params.filletRadius`; дерево fillet тоже не воспроизводит. Union куба r=2 и
r=3 со сферой даёт одинаковый меш. До каскада fillet нужно: (1) строить примитив через
`buildPrimitiveWithFillet(…, params.filletRadius)` во всех трёх местах; (2) воспроизводить `fillet`
в `rebuildBuildTree` (params узла), иначе калибровка 9.9 заблокирует такие CSG. Это меняет
геометрию НОВЫХ CSG с филлет-кубами (сохранённые меши не трогаются — они заморожены).

## 14. Статус 9.5.3 (mirror) — реализовано

Ветка `phase-9.5.3` от `phase-9`. Движок 9.5.2 расширен, не переписан: `SUPPORTED_KINDS += 'mirror'`
(✎ в Timeline и сторож панели подхватили сами), ветки mirror в `patchValid` / `samePatch` / `beforeOf`.
`applyStepPatch` / `stepFingerprint` / `computeCascade` для mirror были с 9.5.0.

**Семантика правки плоскости (R12).** Шаг mirror ничего не хранит готовым (`originalIds`, `ids`, `plane`):
копии, их трансформ (`applyMirrorToTransform`) и список `mirrored[]` (`composeMirroredList` — композиция:
разные плоскости добавляются, одинаковая соседняя отменяет) воспроизводятся из состояния ОРИГИНАЛА на этом шаге.
Поэтому правка заменяет вклад шага: оригинал без зеркал + YZ → `[YZ]`; правка на XZ → `[XZ]` (не `[YZ, XZ]`).
Зеркала ниже перекомпонуются: копия копии `[YZ, XZ]` после правки первого шага на XY → `[XY, XZ]`.
`[YZ, XZ] + XY` как композиция — `[YZ, XZ, XY]` (три отражения), а не `[XY]`: замена касается только правленого шага.
`ids` копий не меняются — каскад идёт по ним (S = ids шага).

**Найдено и исправлено попутно** (воспроизведение расходилось с живым действием и без правки — undo без
снимков, загрузка `.3dtc`; правка шага наследовала ошибку, потому что строится через воспроизведение):
- **MIRROR-CHAIN-REPLAY** — воркер не регистрировал копию примитива в `shapeInfos`; зеркало копии уходило в ветку
  CSG/импорта (мировое отражение кэша) и main thread ещё раз применял весь `mirrored[]` — последняя плоскость дважды.
- **MIRROR-CSG-REPLAY** — копия CSG брала мировые вершины кэша воркера как локальные (двойная трансляция и RS).
  `buildRebuildMeta` даёт копии отражённый локальный меш оригинала (как живое `mirrorSelected`) и включает её в
  `csgResultIds`.
Не проверено: зеркало импортированного меша с поворотом (`import_mesh` — другой путь центрирования воркера).

**UI.** Панель «Шаг N: Зеркало»: радиогруппа YZ / XZ / XY (`role="radio"`, `aria-checked`), выбор применяется
сразу; повторный выбор текущей — ничего. Объект — что зеркалится (`originalIds`).

**Проверка.** WASM (`__tests__/edit-step-mirror.test.ts`): свежий сценарий (pivot < 1e-6, вершины < 1e-5 —
1–2 ULP float32), R12 двойное зеркало, зеркало CSG, `edit_child_params` зеркального ребёнка + калибровка 9.9,
align re-solve, undo/redo со снимками и без, K>1 и повторная правка, отказы, `.3dtc`; «воспроизведение зеркал =
живое» (оба бага). Unit: `composeMirroredList`, проекция (замена вклада, перекомпозиция, XZ∘XZ = тождество),
`computeCascade`. UI: `step-panel-ui.test.tsx`. E2E: `pnpm e2e:edit-step-mirror`.
