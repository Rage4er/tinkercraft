# Шаблон отчёта

Если в задании пользователя дан собственный шаблон — используй его дословно.
Ниже — канонический вариант для задач TinkerCraft.

Заполняй только фактическими данными: числа тестов — из вывода, e2e — из реального прогона,
PR/CI/merge — из `gh`. Не запускал — пиши «не запускался», не выдавай за ✅.

```text
=== <ЗАДАЧА> — ОТЧЁТ ===

1. Контекст: git checkout -b <ветка> main; git log -2; git status
   (HEAD <хеш>, версия <x.y.z>, рабочее дерево <чисто/…>)

2. Реализация:
   - <ключевой пункт 1>: ДА / НЕТ
   - <ключевой пункт 2>: ДА / НЕТ
   - …

3. Тесты:
   - <unit-файл / сценарий>: ✅ / ❌
   - e2e <name>: ✅ / ❌

4. Регресс (e2e):
   smoke ✅ / tree ✅ / plug-and-play ✅ / dimensions ✅ / ux-viewport ✅ /
   selection-outline ✅ / ux-polish ✅ / ortho-raycast ✅ / ux-formats-settings ✅ /
   modeling-tools ✅ / view-modes ✅ / clean-wireframe ✅ / fix-curved-wireframe ✅

5. pnpm typecheck: 0
6. pnpm test: N/N (было M)
7. pnpm build: ✅ / ❌

8. Коммит: <хеш> <feat|fix>: <кратко>

9. PR: <ссылка>, CI: ✅ / ❌, merge: ✅ / ❌, deploy: ✅ / ❌, тег: vX.Y.Z

10. UX-проверка (ручная/Playwright/скриншоты):
    - <сценарий>: ДА / НЕТ
    - …

11. Что НЕ сделано / ограничения:
    - <пункт>
    - <пункт>

=== КОНЕЦ ОТЧЁТА ===
```

## Варианты

- **Архив/демо без кода:** разделы 2–4 заменяются на «Сборка/Артефакт/Проверка»; укажи размер,
  путь, способ проверки (статический сервер, подпапка, отсутствие COOP/COEP) и что коммитов нет.
- **Только проверки:** оставь контекст, прогоны, найденные проблемы, вердикт; не выдумывай изменения.
- **Фикс:** в разделе 2 перечисли баги «до → после» и затронутые файлы.
